# base_agent

> **Maintenance:** see the `lingtai-kernel-anatomy` skill. **Coding agents** update this file in the same commit as code changes. **LingTai agents** report drift as issues/mail/PR proposals; do not silently fix.

Generic agent kernel. Single class `BaseAgent` with methods distributed across 6 helper modules. `__init__.py` retains the constructor, properties, state machine, and subclass-overridable hooks.

> **History note:** there used to be a 7th module, `soul_flow.py`. It was deleted in `1acd183` — soul-domain logic moved to `intrinsics/soul/flow.py`, and the wire-splice logic that lived in it became `tc_inbox.TCInbox.drain_into()`. Mention preserved here only because old patches/discussions reference it.

## Components

- `base_agent/__init__.py` — `BaseAgent` coordinator. Its constructor requires injected `WorkdirLeasePort`, `NotificationStorePort`, `AgentPresenceStorePort`, `LifecycleClockPort`, `SnapshotPort`, and `SourceRevisionPort`; `RefreshWatcherPort` is one of two constructor exceptions — an optional, defaulted-`None` `refresh_watcher` kwarg, so the many pre-existing raw `BaseAgent(...)` construction sites unrelated to refresh are unaffected, while composition roots always inject the production adapter and `_perform_refresh` fails loudly on `None` before any handshake mutation once a real launch command exists (see `src/lingtai/kernel/refresh_watcher/CONTRACT.md`). `BaseAgent` stores only those capabilities and performs no concrete adapter construction (`src/lingtai/kernel/base_agent/__init__.py:379-462`). The optional defaulted-`None` `stream_progress_factory` kwarg is called once with the stable `agent_id` (fail-open) right after identity resolution — only when `streaming` is true; an explicit `streaming=False` never calls it — and its `StreamProgressPort` is passed to `SessionManager(stream_progress=...)`; `streaming` now defaults to `True` (see `src/lingtai/kernel/stream_progress/ANATOMY.md`). The required `lifecycle_clock` is bound to `self._lifecycle_clock` before the first time sample; wall-domain reads (`wall_seconds()`) seed/refresh `_state_changed_at`/`_last_progress_at`, the ACTIVE `_active_turn_started_at`, `_deferred_notifications_oldest_at`, and the event-journal `ts`, while monotonic reads (`monotonic_seconds()`) seed `_idle_since_monotonic` — no Core import/construction of the concrete adapter, no default/no-op form (see `src/lingtai/kernel/lifecycle_clock/CONTRACT.md`). `_sync_notifications` re-arms/reconciles persisted consumer notification delays, then reads the coherent filtered snapshot/fingerprint through the notification Port and preserves the existing state/wake/live-holder order (`src/lingtai/kernel/base_agent/__init__.py:1302-1543`).

- `BaseAgent.submit_turn` / `BaseAgent.cancel_turn` + `kernel/turns.py` / `kernel/execution_workspace.py` / `kernel/turn_events.py` / `kernel/turn_permissions.py` — the protocol-neutral correlated inbound-turn boundary. A private non-mergeable inbox envelope carries one control and optional immutable execution workspace through the serialized AED/tool engine; the run loop binds/resets task-local scope and parallel dispatch copies it into workers. The same path carries a fail-open lifecycle observer and separate fail-closed permission broker; `turn.py` composes permission after risky-action policy and before dispatch. `TurnHandle.result()` settles exactly once, and ACP/session/JSON-RPC vocabulary stays outside Core. Guarded by [BA004](BEHAVIORS.md#behavior-ba004).
- **Puffo admission witness** (`turn.py` `begin_admission_witness_scope` / `scan_and_emit_committed_facts` / `end_admission_witness_scope`, using `kernel/puffo_admission_witness.py`) — at the correlated-turn observer bind, `turn.py` captures a turn-scoped `emitted` set (by toolCallId) plus a monotonic entry-id **watermark** (last interface entry id before the turn; entry ids never rewind, so removals cannot shift the boundary), OUTSIDE the AED retry loop so a replayed entry cannot double-fire. At each **settle point** — after a carrying `agent._session.send(...)` has fully settled (returned, or its exception handling incl. rollback/`_restore_tool_results_after_continuation_failure` has completed) and after each `commit_tool_results(...)` returns — it scans the real `ChatInterface` entries above the watermark; for each un-witnessed `ToolResultBlock` whose content yields a receipt (`extract_admission_receipt`) it emits `ToolResultsCommittedEvent(id, admission_binding(id, raw))` via `turn_events.notify_tool_results_committed`. Reading real wire state is load-bearing: a rolled-back entry is absent and never fires; a survivor of a failed send fires exactly once. The scan never touches a poisoned interface (the `WorkerStillRunning` paths re-raise before any scan). Non-delivery (no observer) is logged `puffo_admission_fact_not_delivered`. The pure receipt/binding half is `kernel/puffo_admission_witness.py` (`extract_admission_receipt`, `admission_binding`); the reliable ACP wire emit is the ACP `_PromptToolObserver.on_tool_results_committed`.
- `kernel/provider_admission.py` — Core-owned typed provider-call Port and
  task-local parent context. A constrained composition wraps the Agent's LLM
  service so every `send`, `send_stream`, and direct `generate` checks this
  Port immediately before provider I/O. `turn.py` binds a root parent only
  after its final origin admission and resets it on turn/loop teardown.
  Adapters own authentication and transport; Core does not encode ACP, sockets,
  paths, or a serializable bearer token here. The operator procedure and
  failure modes are in [`docs/references/provider-admission.md`](../../../../docs/references/provider-admission.md).
  Guarded by [BA005](BEHAVIORS.md#behavior-ba005).
- `BaseAgent._sleep_alarm_lock` / `_sleep_alarm_problem_signature` (`base_agent/__init__.py`) — narrow per-agent state shared only by `system.sleep(delay=...)` arming and lifecycle heartbeat expiry. It prevents expiry from consuming a later replacement alarm and bounds malformed-file diagnostics; it is not a scheduler or notification-store lock.
- `BaseAgent._request_turn_cancel` / `_cancel_event` — the private, idempotent producer and process-global cooperative turn latch (`src/lingtai/kernel/base_agent/__init__.py:1231-1233`). Heartbeat signal-file producers route through it after consuming their files (`src/lingtai/kernel/base_agent/lifecycle.py:611-659`); successful refresh routes through it after watcher spawn and before shutdown (`src/lingtai/kernel/base_agent/lifecycle.py:1114-1129`); the official declared System host and retained direct compatibility adapter invoke it only after ASLEEP state/event publication (`src/lingtai/adapters/tool_plugin_host.py:1296-1299`, `src/lingtai/tools/system/karma.py:167-172`). Ownership and limits are normative in `CONTRACT.md` clause `agent-runtime.turn-cancel-latch.v1`.
- `base_agent/identity.py` — Identity, manifest, and status (~315 lines). `_set_name` (`base_agent/identity.py:29`), `_set_nickname` (`base_agent/identity.py:42`), `_update_identity` (`base_agent/identity.py:48`), `_LLM_PUBLIC_KEYS` safelist constant (`base_agent/identity.py:73`), `_build_manifest` (`base_agent/identity.py:76`), `_safe_llm_from_service` (`base_agent/identity.py:117`) — surfaces a sanitized `llm` block (provider/model/base_url, safelisted) from the live `LLMService` instance for `.agent.json` and the identity prompt section (issue #78). Never reads from `init.json` (kernel stays preset-oblivious); preset metadata is added by the wrapper's `Agent._build_manifest` override. `_status` (`base_agent/identity.py:197`) reads `_lifecycle_clock.monotonic_seconds()` for uptime and `.wall_seconds()` for the no-progress/active-turn/heartbeat ages. `_safe_llm_from_service` is also reused (imported directly, not duplicated) by `kernel.session_stats.build_agent_record` for the Agent record's `model` block.
- `__init__.py::_write_session_stats_record` / `_build_agent_record_extra` — publish the Agent Record (`system/agent_record.json`) beside `.status.json`, throttled by `LINGTAI_SESSION_STATS_REFRESH_SECONDS`; its explicit `RecentDaemonSnapshot` schedules/coalesces ledger-selected daemon reads without blocking heartbeat publication; `_build_agent_record_extra` is the Core-side extension point `lingtai.Agent` overrides for MCP/handle metadata. Called from the same three hooks as `_write_status_snapshot` (`_save_chat_history`, the ACTIVE watchdog, `_write_heartbeat_tick`). See `kernel/session_stats/ANATOMY.md` and `CONTRACT.md`.
- `base_agent/lifecycle.py` — Heartbeat, signal-file detection, start/stop, refresh, hidden IDLE→ASLEEP timeout, nudge dispatch (~905 lines; the watcher program's own source moved to `refresh_watcher/watcher_program.py`, see below). **Token restore (agent-session rebuild)**: on `_start`, after chat-history restore, `agent.rebuild_agent_session()` rebuilds the current molt generation's since-molt token aggregate from the durable trajectory (optimized indexed/reverse-scan path) and `restore_token_state` is **seeded from that rebuilt aggregate** — so a refresh/restart preserves since-current-molt `token_usage.session` totals instead of restoring LIFETIME `token_ledger.jsonl` totals (the #679-class defect). The lifetime `sum_token_ledger` restore remains only as a back-compat fallback when the event-based rebuild is unavailable (brand-new agent, tier `none`, or an unexpected error). Key functions — `_start` · `_stop` · `_shutdown_daemon_runtime` · `_start_heartbeat` · `_stop_heartbeat` · `_heartbeat_loop` · `_perform_refresh` · `_can_fallback_preset` · `_check_rules_file` *(function-name anchors, not line numbers — line citations drift with every edit; grep the name in `base_agent/lifecycle.py` for the current location).* **Typed fail-closed stop proof:** public `StopResult`/`StopStatus` distinguish `STOPPED` from `TIMED_OUT`; one deadline waits for both run-loop thread and retained poisoned-provider Future, and timeout returns before Task Card, Agent-service, daemon/session/mail/journal, manifest, heartbeat, or lease teardown. The quiescent branch alone enters the post-proof issue-661 release `finally`. **Main-loop stop-wake**: immediately after `_stop` sets `_shutdown`, it posts one no-payload `MSG_TC_WAKE` into `agent.inbox` (guarded by `getattr(agent, "inbox", None)`, `base_agent/lifecycle.py:265-268`) so the main `_run_loop` returns from its blocking `inbox.get(timeout=_inbox_timeout)` at once instead of waiting out the poll interval. This does **not** lower the permanent `_inbox_timeout`; `_run_loop` re-checks `_shutdown` after each dequeue so the wake never becomes a turn (see the `turn.py` entry). **Daemon teardown contract**: `_stop` calls `_shutdown_daemon_runtime` after joining the main loop but before closing session services, stopping heartbeat, or releasing the workdir lock. If the daemon capability is present, `DaemonManager.shutdown_for_agent_stop()` kills tracked CLI process groups and shuts down executor pools while `.agent.heartbeat` is still fresh, preventing refresh watchers from seeing a dead heartbeat/clear lock while the old Python interpreter is still held alive by daemon workers. **Heartbeat-file lifetime contract**: `.agent.heartbeat` is created on `_start_heartbeat` and unlinked at the **end** of `_stop` (just before the workdir-lease `release`), so external observers — TUI launcher, `lingtai-tui list`, `lingtai-tui purge` — see the workdir as live for the entire teardown window. The heartbeat loop intentionally keeps writing fresh timestamps after `agent._shutdown.is_set()` (loop predicate is `agent._heartbeat_thread is not None`); only signal-file detection is gated on `_shutdown`. **Interruptible-cadence contract**: the 1s beat is an interruptible `agent._heartbeat_stop.wait(HEARTBEAT_TICK_SECONDS)` on **both** loop branches (the shutdown/not-ready branch `base_agent/lifecycle.py:393` and the main-body branch `base_agent/lifecycle.py:644`), where `_heartbeat_stop` is a dedicated `threading.Event` initialized beside `_heartbeat_thread` (`base_agent/__init__.py:725`) and distinct from `_shutdown`. `_start_heartbeat` clears it (`base_agent/lifecycle.py:346`) before every new heartbeat thread, and **only** the final `_stop_heartbeat` sets it (`base_agent/lifecycle.py:362`) — after nulling `_heartbeat_thread` and before the post-join `.agent.heartbeat` unlink — so the final stop wakes the cadence at once while every earlier teardown step keeps beating on the same 1s interval. Without this contract, a quick suspend→relaunch would race a still-living interpreter into the same workdir (the kernel's flock prevents data corruption but two Python processes still appear in `ps`). **Nudge dispatch**: just before the notification sync poll, the heartbeat loop imports/calls `_run_nudge_checks(agent)` (`base_agent/lifecycle.py:539-540`), wrapped in `try/except` that logs warnings. Cheap Nudge evaluation writes through `nudge.upsert` / `nudge.remove`; folder-size and event-journal observations are coalesced background work, so their tree/history reads never hold the heartbeat. See `nudge/ANATOMY.md`. **Hidden idle timeout + notification sync poll**: before notification sync, `_maybe_sleep_after_idle_timeout` moves agents that stayed IDLE for `IDLE_SLEEP_TIMEOUT_SECONDS` (24h) to ASLEEP, saving chat history and logging `idle_sleep_timeout`; this replaces the old agent-visible stamina countdown and is not surfaced through init.json, prompt, status, or tool metadata. The heartbeat loop then calls `agent._sync_notifications()`, wrapped in a `try/except` that logs warnings without aborting the tick. This is the primary trigger for `.notification/` filesystem reads (including the `nudge.json` file the dispatch may have just written). **Refresh dispatch contract**: `_perform_refresh` calls `agent._build_launch_cmd()` as a bound method — must NOT be re-introduced as a module-level function (would shadow the `Agent` subclass override and silently no-op every user refresh). See issue #7 — confirmed in vivo against deepseek_pro 2026-05-05 (`refresh_start → refresh_no_launch_cmd` in 0.78ms, PID stable across 5 "refreshes"). **Refresh handshake self-sufficiency**: `_perform_refresh` is called from three sites — the heartbeat (`.refresh` signal-file path), the `system(action='refresh')` intrinsic, and the AED preset-fallback in `turn.py`. All three reach the same code without coordination, so `_perform_refresh` normalizes the on-disk handshake (`.refresh.taken` ack file present and `.refresh` cleared) before spawning the watcher subprocess, and, after spawn, requests cooperative turn cancellation through `agent._request_turn_cancel()` before setting `agent._shutdown` so the lock-release phase completes regardless of caller. The `refresh_deferred_relaunch` event records `handshake` ∈ {`preexisting_taken`, `renamed_refresh`, `synthesized_direct_call`, `synthesized_after_rename_failed`, `ack_write_failed`} for telemetry; if the ack cannot be established, `_perform_refresh` logs `refresh_ack_failed` and returns before spawning a watcher or setting shutdown. Direct callers thus never trip the watcher's `phase='ack'` or `phase='lock'` timeouts in the normal established-ack path. **Refresh single-flight slot (LABT BA002)**: `_perform_refresh` claims the process-lifetime slot `agent._refresh_started` under `agent._refresh_singleflight_lock` before any side effect, so near-concurrent requests coalesce into one watcher (lingtai#624; a coalesced request logs `refresh_skipped` with `reason=refresh_already_in_progress`). The pre-handoff body runs inside one `try/finally`: every ordinary failure return (`refresh_no_launch_cmd`, `refresh_ack_failed`) and every exception raised before `spawn_detached(request)` returns — including one from the bound `_build_launch_cmd()` (in the wrapper, `venv_resolve.resolve_venv`'s configured-`venv_path` precheck), from the missing-Port check, from request construction, or from the spawn itself — releases the slot and signals no `_cancel_event`/`_shutdown`, so the live process can retry a corrected refresh. The on-disk handshake is a separate matter: failures before handshake normalization (no launch command, raising builder, missing Port) touch neither `.refresh` nor `.refresh.taken`, but the `finally` does not roll back an ACK that was already established, so an exception after normalization (request construction, raising spawn) may leave `.refresh.taken` in place and the retry then logs `handshake=preexisting_taken`. Only a completed handoff (the Port's normal return) is terminal: after `spawn_detached` returns the slot stays claimed for the rest of the process lifetime even if the `refresh_deferred_relaunch` logging or the `_cancel_event`/`_shutdown` signaling after it fails. Before this was enforced, a raising launch-command build left the slot claimed and every later refresh was silently skipped until a process restart. **Refresh stale-process recovery**: if the watcher relaunch is rejected by the CLI duplicate-process guard (`another lingtai agent is already running`) and the blocking process is still a same-workdir `lingtai run` with no fresh heartbeat, the watcher logs `refresh_watcher_stale_duplicate_*`, sends `SIGTERM`, escalates to `SIGKILL` after a short grace period, and retries. A fresh heartbeat blocks cleanup and logs `refresh_watcher_duplicate_alive` instead. **Terminal refresh failure visibility**: when all `MAX_ATTEMPTS` relaunch attempts are permanently exhausted, the watcher makes the dead agent diagnosable rather than silently gone — `_publish_refresh_failed_permanent` writes a bounded `logs/refresh_failed_permanent.json` artifact and appends a high-priority `refresh_failed_permanent` event (`source="refresh"`, `ref_id="refresh_failed_permanent"`) to `.notification/system.json`, both carrying the same `failure_state` metadata (attempts, last/duplicate/relaunch PID, heartbeat age+status, bounded stderr tail, cleanup action/result/error, relaunch error, stderr-log path, and `recovery_guidance`). A final `refresh_failed_permanent` event is also logged to `logs/events.jsonl`. It does not delete `.agent.lock` or change retry/restart semantics. **Refresh watcher program source moved (S8 slice)**: `_perform_refresh` no longer builds the watcher's ~365-line program-source string inline. It builds an immutable `RefreshWatcherRequest` (`src/lingtai/kernel/refresh_watcher/__init__.py`) from the handshake paths, launch `cmd`, agent name/address, and `identity_fields_json` (a `json.dumps(agent._runtime_identity_event_fields)` snapshot taken at this call site — not a live dict or shallow container, because the identity payload nests a mutable `kernel_runtime` sub-dict that a shallow copy would still alias), then calls `agent._refresh_watcher.spawn_detached(request)` once. `refresh_watcher.watcher_program.render_watcher_script(request)` — Core-owned, pure, no OS calls — renders the exact same program text this module used to build inline; the POSIX adapter's `build_watcher_env(request)` (`src/lingtai/adapters/posix/refresh_watcher.py`) renders the process environment (`os.environ` capture plus `LINGTAI_REFRESH_ENV_OVERWRITE=1` when `request.env_overwrite`). See `refresh_watcher/ANATOMY.md`, `refresh_watcher/CONTRACT.md`, and `refresh_watcher/MANUAL.md` for the Port/Adapter/manual detail; this entry keeps only the historical behavior narrative for readers descending from `base_agent/`.
**Refresh watcher event redaction**: the watcher subprocess persists its own `refresh_watcher_*` events to `logs/events.jsonl` through an inline `log()` (rendered by `refresh_watcher/watcher_program.py:168-183`) that runs in a separate process and therefore does **not** pass through `CompositeLoggingService.log` / `redact_for_trajectory`. That inline `log()` imports `lingtai.kernel.trace_redaction.redact_for_trajectory` (the whole-entry redactor, not just `redact_text` value-walking) and applies it to the full event dict before the JSONL write, so secret-shaped values reaching `stderr_tail` (relaunched-process stderr, e.g. a config traceback echoing a token), `cmdline`, and `error` previews are redacted to `<REDACTED:*>` placeholders before persistence — and, for key-aware parity with normal trajectory logging, values under secret-named keys are removed even when they do not match a known token shape. The redaction is fail-open for relaunch reliability but **not silent**: if the redactor cannot be imported the event carries a non-secret marker `redaction_unavailable=True`, and if `redact_for_trajectory` raises at apply time the event is rebuilt from only known-safe scalar fields (`type`/`address`/`agent_name`/`ts`) with `redaction_unavailable=True` and `redaction_error=True` — the unredacted `**kw` fields are dropped rather than persisted raw. The watcher path thus matches the in-process redaction contract documented in the root anatomy's `trace_redaction.py` entry while making degradation diagnosable; the shared terminal-failure metadata builder likewise redacts the bounded `last_stderr_tail`, `last_cleanup_error`, and `last_relaunch_error` (S8 bugfix: the latter two were previously raw/unbounded) before writing `refresh_failed_permanent.json`, `.notification/system.json`, or the final `refresh_failed_permanent` event; if the watcher subprocess cannot import the redactor or the redactor raises, it marks `redaction_unavailable` and replaces each with a `REDACTED` sentinel instead of leaking raw text.
- `lifecycle.py::_fire_sleep_alarm_if_due` — heartbeat-owned persisted alarm consumer. Under `agent._sleep_alarm_lock`, it reads only `<workdir>/.alarm`, no-ops before its Decimal wall deadline, and at/after it calls `_enqueue_system_notification` with a stable stored-deadline-derived identity before consuming the file. Publish failure remains retryable; malformed or unreadable content stays in place with one bounded diagnostic per unchanged problem.
- `base_agent/turn.py` — Turn engine: main loop, message dispatch, AED, response processing, and ACTIVE-turn tool-call progress-meter wiring (use the function-name anchors below; line count intentionally omitted). Transient provider retry helpers (`_exception_status_code` / `_is_transient_provider_error` in `base_agent/turn.py`) classify SDK/network 5xx-ish failures and `EmptyLLMResponseError` before they spend AED budget. `WorkerStillRunningError` (from `llm_utils.py`) is handled directly in the AED loop: the worker interface is marked poisoned (see `worker_recovery.py`), a bounded/redacted recovery artifact is written, a high-priority `kernel.llm_worker_hang` notification is published, a skip-save forced refresh is requested, and the agent is put STUCK→ASLEEP with `skip_post_turn_save=True` so the in-process `ChatInterface` is never mutated while the worker future is still alive — refresh/relaunch brings up a fresh interface from the last safe on-disk history. A residual poison guard at the top of the AED `try` also short-circuits any later turn that reaches the loop while poisoned. No filesystem sentinel — the previous `.llm_hang` watchdog/sentinel system was removed because its 120s timer false-fired on slow thinking-model turns and the sentinel could block wake-from-asleep even after a successful refresh. Run loop — `_run_loop` · `_concat_queued_messages` · `_handle_message` · `_handle_request` · `_handle_tc_wake` *(function-name anchors, not line numbers — line citations drift with every edit; grep the name in `base_agent/turn.py` for the current location).* **Fresh-dequeue cancellation ownership and stop-wake:** immediately after each blocking `inbox.get` returns, both branches re-check shutdown before any turn publication. The ASLEEP branch then clears the stale latch before publishing ACTIVE and merging (`src/lingtai/kernel/base_agent/turn.py:951-973`); the awake branch clears it before `_concat_queued_messages` and before ACTIVE (`src/lingtai/kernel/base_agent/turn.py:975-988`), so a cancellation arriving during merge survives. These are the only production clears. `_process_response` has no entry or branch clear: its pre-dispatch and post-tool checkpoints observe the latch, suppress dispatch/continuation, preserve required tool-result commits, and leave the latch set (`src/lingtai/kernel/base_agent/turn.py:2354-2366`, `src/lingtai/kernel/base_agent/turn.py:2529-2544`). ASLEEP notification synchronization may move the agent IDLE and enqueue `MSG_TC_WAKE`, but does not consume cancellation (`src/lingtai/kernel/base_agent/__init__.py:1898-1914`). The `_stop` stop-wake still unblocks either dequeue promptly and is rejected by the shutdown re-check rather than becoming a turn. `_handle_tc_wake` — **post-redesign: drives one inference round off the existing canonical interface via `session.send(None)` when the tail is `user[ToolResultBlock]` (the shape produced by `_inject_notification_pair`).** Legacy `tc_inbox.drain()` items are still spliced in the old way (call appended here, result passed through send) at the top of the function for back-compat, but the queue is always empty in production. The wire-drive path is what makes notifications visible to the LLM: no fake user message, no meta prefix. **No-candidate terminal guard:** a deterministic `NoCandidateError` bypasses AED/session rebuild, merges safe `diagnostic_fields()` into `no_candidate_terminal`, reports the terminal task-card error, sets ASLEEP, and breaks (`base_agent/turn.py:694-715`). **Render-safe terminal classification:** the turn consumes `llm_replay_terminal_flags` from the shared kernel LLM boundary before calling `safe_exception_description`; exact kernel-wrapper flags avoid all provider marker storage, hooks, or coercion, while the shared nested `str`/`repr`/class-label fallback prevents hostile renderers from escaping either the adapter or the run loop. **Partial-stream terminal guard:** before transient/AED classification, an exception marked `_lingtai_partial_stream` logs `llm_partial_stream_terminal`, skips chat-history save and session rebuild/replay, and ends the turn because provider output was already visible (`base_agent/turn.py:717-729`). **Exhausted provider-recovery guard:** an adapter-final exception carrying the shared exact `_lingtai_no_aed_retry` flag logs `llm_no_aed_retry_terminal`, reports a terminal provider error, sets the ASLEEP gate, and bypasses transient retry/AED/session rebuild so the request cannot escape its provider-owned retry budget. **AED state transitions** (within `_run_loop`): transient provider failures first get up to three local retry attempts with 1/2/4s backoff, pending-tool-call healing, and `system.stuck_revive` retry messages, but without incrementing `aed_attempts` or rebuilding the session (`base_agent/turn.py:792-833`). Counted AED attempts then close pending tool calls with synthesized results (`base_agent/turn.py:842-852`), set STUCK (`base_agent/turn.py:854`) before rebuilding the session (`base_agent/turn.py:923-925`), and set ACTIVE again right before re-entering `_handle_message` with the recovery message (`base_agent/turn.py:927-929`). Without that ACTIVE flip, a recovered turn that does long work (file writes, mail, bash) leaves `.agent.json:state` reading "stuck" until the post-turn sweep at `base_agent/turn.py:931-946` starts writing `sleep_state` (IDLE) — visible to the TUI/portal as a stale "滞" badge while the agent is in fact busy. `_get_guard_limits` and `_process_response` (function-name anchors, as above; `_process_response` raises `EmptyLLMResponseError` on an empty response). **Tool errors stay in the normal result flow**: `_process_response` no longer has a repeated-identical-tool-error hard-stop or `session.send(str)` continuation path. Tool execution errors remain ordinary `ToolResultBlock` payloads that are sent back through `session.send(tool_results)`; `ToolExecutor` enriches those error payloads with model-visible `tool_error` recovery metadata (`_tool_error_meta` / `_attach_tool_error_meta` in `tool_executor.py`) while the generic tool-loop / emergency limits remain the only backstop for true infinite loops.
- `llm/base.py` — `is_all_empty_response(response)` (`src/lingtai/kernel/llm/base.py:167-175`) is the pure shared semantic-empty predicate: normalized text, tool calls, and thoughts must all be empty; no daemon lifecycle or recovery policy lives here.

- `base_agent/worker_recovery.py` — WorkerStillRunning poison/recovery helpers (design ref: PR #298). When the LLM worker is still alive after timeout + grace, the in-process `ChatInterface` is poisoned for this process and recovery happens from durable on-disk state after refresh/relaunch. `build_worker_hang_context` captures safe message/exception metadata (never the poisoned interface); `write_worker_hang_artifact` writes a bounded/redacted `history/unfinished_turns/worker_still_running_*.json` (no raw chat, tool args, or tool results); `mark_worker_interface_poisoned` sets process-local poison state (`agent._llm_worker_interface_poisoned` et al.); `is_worker_interface_poisoned` is the guard predicate read by `turn.py`/`__init__.py`; `publish_worker_hang_notification` publishes a high-priority `kernel.llm_worker_hang` / `worker_still_running:*` system event (idempotent on ref_id); `request_worker_hang_refresh` calls `_perform_refresh(skip_chat_history_save=True, ...)` once (idempotent); `resolve_worker_hang_artifact` marks the matching unfinished-turn artifact `resolved` when its system event is dismissed; `rehydrate_worker_hang_recovery` (called from `lifecycle._start`) re-surfaces only open artifacts as notifications after restart; `maybe_prepend_worker_hang_recovery_prompt` (called from `_handle_request`) prepends one concise recovery notice to the next safe text request.
- `base_agent/tools.py` — Tool surface: schemas, dispatch, registry. `_dispatch_tool` (`base_agent/tools.py:14-33`), `_refresh_tool_inventory_section` (`base_agent/tools.py:47-94`) is OPT-IN and DEFAULT OFF behind `LINGTAI_TOOL_PROSE_SECTION_ENABLED` (`kernel/config.py:tool_prose_section_enabled`): by default it deletes any existing `tools` section and returns, because the prose it renders duplicates the tool-calling schema description the provider wire already carries (`kernel/llm/base.py:wire_tool_description`); when opted in it appends the selected-language glossary body to each tool's description via `tool_glossary.append_tool_glossary`, `_build_tool_schemas` (`base_agent/tools.py:53-101`) injects the standard `reasoning` property into every tool schema, `_add_tool` (`base_agent/tools.py:104-132`), `_remove_tool` (`base_agent/tools.py:135-143`), `_override_intrinsic` (`base_agent/tools.py:143-155`), `_has_capability` (`base_agent/tools.py:158-160`).
- `base_agent/prompt.py` — System prompt building, flushing, updating (80 lines). `_build_system_prompt` (`base_agent/prompt.py:26-37`), `_build_system_prompt_batches` (`base_agent/prompt.py:40-56`), `_flush_system_prompt` (`base_agent/prompt.py:59-66`), `_update_system_prompt` (`base_agent/prompt.py:69-80`).
- `base_agent/messaging.py` — mail arrival and system-event production. `_enqueue_system_notification` makes its dedupe/append decision from the current `system` payload in one Store compare-update and consumes event identity from `CompareUpdateResult.value`; no caller-held channel lock remains (`_enqueue_system_notification` in `src/lingtai/kernel/base_agent/messaging.py` — function-name anchor, not a line range).

## Connections

- All submodules are leaves — they import nothing from `base_agent/`. Cross-module communication is mediated through the `agent` parameter (the BaseAgent instance).

- `__init__.py` imports from all submodules lazily (inside method bodies) to avoid circular imports at load time. Soul-flow pass-throughs resolve the soul intrinsic through the injected registry (`BaseAgent._intrinsic_hook("soul", ...)`), no longer by import — the kernel cannot import `tools`.
- `__init__.py` → the required `NotificationStorePort` for sync snapshot/fingerprint and → `notifications.py` for Core policy.
- `__init__.py` constructs `SessionManager` without notification-specific send hooks; notification delivery is owned by `_sync_notifications` plus the ACTIVE canonical-payload attach step in `turn.py`.
- `__init__.py` → `SessionManager` runtime reasoning effort: `reasoning_effort_status()` / `set_reasoning_effort(value)` / `clear_reasoning_effort()` are thin verbatim delegations to the manager-owned controller (`src/lingtai/kernel/ANATOMY.md`, `src/lingtai/kernel/llm/ANATOMY.md`). In-process and self-facing only — no system tool action, file protocol, CLI/TUI command, or daemon control sits behind them, and they never propagate to a running daemon.
- `__init__.py` → `event_journal.EventJournalPort`: `_log` assembles event fields — including the wall-domain `ts` from `_lifecycle_clock.wall_seconds()` — and invokes `append()` (`base_agent/__init__.py:1058-1059`); the quiescent `STOPPED` branch invokes `close()` best-effort after session/mail teardown and before final manifest, heartbeat withdrawal, and lease release; `TIMED_OUT` closes nothing.
- `__init__.py` / `lifecycle.py` → `workdir_lease.WorkdirLeasePort`: the constructor stores the required Port and acquires it once with a 10s grace (`base_agent/__init__.py:414-420`); the signature-preserving rollback decorator releases best-effort only after successful acquisition and re-raises the original construction failure (`base_agent/__init__.py:260-271`). `_stop` retains it on typed timeout and releases it last only after execution quiescence, final manifest write, and heartbeat withdrawal; the post-proof release remains in `finally`. See `src/lingtai/kernel/workdir_lease/ANATOMY.md`.
- `__init__.py` / `identity.py` / `lifecycle.py` → `lifecycle_clock.LifecycleClockPort`: all three read only `agent._lifecycle_clock.wall_seconds()` / `.monotonic_seconds()`. `lifecycle._write_heartbeat_tick` assigns `agent._heartbeat = wall_seconds()` and passes the raw float to `agent._agent_presence.publish_heartbeat`; `lifecycle._start`/`_reset_uptime` anchor `_uptime_anchor` with `monotonic_seconds()`; the heartbeat loop takes one shared monotonic tick for the snapshot/GC interval checks and a wall read for the ACTIVE no-progress watchdog age; `identity._status` reads monotonic for uptime and wall for the no-progress/active-turn/heartbeat ages. Both `agent._heartbeat_stop.wait(HEARTBEAT_TICK_SECONDS)` cadence sites, the refresh-watcher subprocess source-string clocks, and the synthetic notification/event-ID clocks stay direct and are NOT routed through the Port. When present, it builds an immutable `RefreshWatcherRequest` (handshake paths, launch `cmd`, agent name/address, `identity_fields`) and calls `agent._refresh_watcher.spawn_detached(request)` exactly once, after the `.refresh`/`.refresh.taken` handshake establishes the ACK invariant and before calling `agent._request_turn_cancel()` and then setting `agent._shutdown`. `lifecycle.py` no longer builds the watcher's program-source string or process environment itself — `refresh_watcher.watcher_program.render_watcher_script(request)` (Core-owned, pure) renders the program text, and the POSIX adapter's `build_watcher_env(request)` renders the process environment. ## State

- `_event_journal` is optional injected process-local ownership. Raw Core instances may leave it `None`; storage state belongs to the selected outer adapter (`base_agent/__init__.py:409`, `base_agent/__init__.py:1058-1059`).
- `identity.py` mutates `.agent.json` (manifest) and `system/system.md` (identity prompt section) via `_build_manifest` (`base_agent/identity.py:76-114`) and `_update_identity` (`base_agent/identity.py:48-65`). The manifest now includes a sanitized `llm` block (`provider`, `model`, `base_url`) read from the live `LLMService` via `_safe_llm_from_service` (`base_agent/identity.py:117-154`). The wrapper subclass extends with `preset` (active/default/allowed) read from `init.json` and re-applies the LLM safelist for defense-in-depth — see `src/lingtai/agent.py`. The identity prose renderer (`base_agent/__init__.py:137-243` inside `_build_identity_section`) folds both blocks into the cached system-prompt prefix only when present, so bare BaseAgent instances stay quiet. It renders `created_at` ("born") but deliberately omits `started_at`: session start changes on every process restart, including a plain refresh with no source/config change, and would otherwise invalidate the cached prefix. `started_at` remains in the manifest and disk identity state — only this prompt render omits it.
- `lifecycle.py` publishes the heartbeat through the injected presence Port from `_write_heartbeat_tick` (where `agent._heartbeat = _lifecycle_clock.wall_seconds()` is passed to `publish_heartbeat`; the resulting `.agent.heartbeat` file's lifetime equals the Python process's lifetime — see "Heartbeat-file lifetime contract" above), consumes signal files (`.interrupt`, `.refresh`, `.suspend`, `.sleep`, `.prompt`, `.clear`, `.inquiry`, `.rules`), checks the single root `.alarm` absolute deadline under `BaseAgent._sleep_alarm_lock`, and reads `.notification/*.json` via `_sync_notifications` on every tick. At a due alarm the lifecycle owner calls the existing ordinary system-event producer, then the normal notification sync owns ASLEEP wake; malformed `.alarm` content remains in place and logs once per unchanged problem.
- `turn.py` owns stale cancellation-latch consumption at the two fresh-dequeue boundaries and nowhere else; inner response/tool consumers only observe the latch through logical-turn exit. It writes `history/chat_history.jsonl` via `_save_chat_history` (delegated to `__init__.py`), writes `.status.json` and `logs/token_ledger.jsonl`, and mutates the not-yet-committed current notification holder on final tool results by adding/removing the canonical `_meta.agent_meta.notifications.attention` + `_meta.agent_meta.guidance.transient` payload. Previously committed historical holders are not mutated by this path. **AED compaction exception (issue #144)**: before either AED retry branch, `_compact_history_before_retry` intentionally rewrites already-committed `ToolResultBlock.content` larger than the 5K retroactive cap into the same `lingtai_tool_result_spill` manifest shape — entries / ids / pairing / `synthesized` flag are preserved. This is a separate compaction exception to the historical-retention rule. The helper logs a single bounded summary event `aed_history_compacted` and persists the compacted history before replay. The rest of the turn path constructs the per-turn `ToolExecutor` and handles result spilling as documented above.
- Notification persistence is owned by the injected Store. `messaging.py` atomically updates `system`; email and other producers publish through strict agent-bound Core helpers. Consumer delay adds only private `.notification/.delay_state.json` plus its `delay-alarm` mirror: `_sync_notifications` re-arms the process timer and coherent reads recover expired delay state before filtering/delivery, so restart cannot leave a target silently hidden. A `daemon` delay target is masked instead of filtered — its payload and raw version stay in the coherent read while its attention entry becomes a constant token — and `_sync_notifications` refreshes the bounded `agent_state.daemon` summary on every stable read, including the quiet/masked/delayed ones.
- `lifecycle._perform_refresh` owns two process-local, never-persisted fields: `agent._refresh_singleflight_lock` (a lazily created `threading.Lock`) and `agent._refresh_started` (the single-flight slot). The slot is `True` only while a refresh attempt is between claiming it and a failed pre-handoff exit, or permanently after a completed `spawn_detached` handoff; it is never left `True` by a failed or raising pre-handoff attempt (see the lifecycle entry above and LABT BA002).
- `worker_recovery.py` writes `history/unfinished_turns/worker_still_running_*.json` (bounded/redacted unfinished-turn artifacts; atomic tmp+rename), marks dismissed artifacts `resolved` without deleting them, and marks `prompt_injected_at` on the first safe request after restart. The poison flag and related `_llm_worker_*` fields are process-local in-memory state only (never persisted). `lifecycle._start` reads open artifacts via `rehydrate_worker_hang_recovery` to re-publish the high-priority notification after relaunch.
- `_inject_notification_pair()` still emits compact `notification_pair_injected` metadata for session summaries, while `_log_notification_block_injected()` records the durable actual-block history (`mode`, `call_id`, `sources`, full `_meta` envelope with `tool_meta`, `agent_meta`, `guidance`, `notifications`, and the compact `notification_guidance` ref/hook) for TUI `/notification` and log readers (`__init__.py:1603`, `__init__.py:1957`). It also writes a durable synthetic `tool_result` recovery record (`origin="kernel_notification_sync"`) that `tool_result_recovery.py` replays origin-gated after a provider/WS rollback; a `redacted=true` replay makes `_recover_pending_tool_result` reset the committed fingerprint (`notification_redacted_replay_resync`). Contract: `src/lingtai/services/LICC_NOTIFICATION_CONTRACT.md` ("Synthetic pair durability and heal replay").

## Notes

- **LICC notification contract:** changes to notification sync, live-holder movement, `_meta.agent_meta.notifications.attention`, `_meta.agent_meta.notifications.persistent`, persistent notification delivery state, or producer authority/dismissal boundaries must check `src/lingtai/services/LICC_NOTIFICATION_CONTRACT.md` in the same change.
- **`__init__.py` is large.** This is intentional — the constructor, properties, state machine, hooks, cross-cutting infrastructure (`_save_chat_history`, `_log`, notification sync, legacy tc_inbox drain), and pass-through stubs all live here. The package is not "thin shell + 6 leaves"; the remaining code is genuinely cross-cutting or bound to the class definition.
- **Pass-through pattern.** Each extracted method becomes a 2-line stub in `__init__.py` (lazy import + call). This preserves the `BaseAgent` class interface while the implementation lives in submodules. The `self` → `agent` conversion is mechanical but `_heartbeat_loop` (~264 lines, 15+ cross-cluster calls) deserves extra-careful review.
- **Subclass overrides stay on `__init__.py`.** `_activate_preset`, `_activate_default_preset`, `_build_launch_cmd`, `_pre_request`, `_post_request`, `_on_tool_result_hook`, `_cpr_agent` are all overridden by the `Agent` subclass in the wrapper package. They must remain as methods on `BaseAgent`.
- **Messaging Task Card route capture (legacy context only).** The automatic Task Card remains a mechanical, bounded broadcast of the agent's own authoritative `logs/events.jsonl`, owned by the Telegram and Feishu MCP adapters (see `src/lingtai/mcp_servers/ANATOMY.md`). The public programmable capability has moved to the intrinsic `src/lingtai/tools/task_card/` producer, whose contract is one agent-local artifact under `taskcard/`. BaseAgent still derives and clears `_telegram_task_card_context` around Telegram turns, but neither consumer uses that route: Telegram and Feishu independently read `taskcard/status` and `taskcard/taskcard.md` and project the artifact into their own resident programmable slots. `_on_tool_result_hook` remains a defined (currently no-op) subclass extension point, not a Task Card hook. The one kernel adaptation that matters to automatic slots is structural provenance: `turn.py` records canonical response `diary` text with the provider `api_call_id`; hidden `thinking` events remain separate and are not projected.
- **All-empty recovery boundary (Draft #1055).** Main and daemon share only the pure `LLMResponse` predicate `is_all_empty_response` (`src/lingtai/kernel/llm/base.py:167-175`): text, tool calls, and thoughts must all be empty; thoughts-only output is not empty. Main owns ACTIVE/STUCK/ASLEEP lifecycle transitions and its initial + three same-session transient retries (1/2/4 seconds), pairing heal/compaction, localized `system.stuck_revive`, then counted AED rebuilds. The daemon Anatomy is the reciprocal route for the same retry/AED semantics inside its daemon-owned loop, but daemon error descriptions and localized recovery `MSG_REQUEST`s are daemon-local; no BaseAgent private helper crosses the boundary. Main owns ACTIVE/STUCK/ASLEEP; daemon owns cancel/timeout/max-turn and detached terminal FAILED translation; neither lifecycle is shared.
- **Public-family ownership (current slice).** `task_card` is now an intrinsic `lingtai.tools` family registered independently of messaging channels. Its producer contract is channel-neutral and writes only the agent-local `taskcard/` artifact. Telegram and Feishu are consumer-only adapters; neither owns a public `task_card` MCP family.

- **Intrinsic Task Card producer.** The public `task_card` tool now lives at `src/lingtai/tools/task_card/`. It validates a renderer within the agent workdir, writes `taskcard/taskcard.md` atomically, writes `taskcard/status` as exact `active` or `inactive`, keeps one active watch per agent, and emits deduped `task_card.error` / `task_card.limit` notifications. `lifecycle._stop` calls `shutdown_for_agent_stop` on the intrinsic manager so the updater stops with `inactive` written first. Consumer-specific projection and resident composition are documented under `src/lingtai/mcp_servers/telegram/task_card/` and `src/lingtai/mcp_servers/feishu/task_card.py`.
